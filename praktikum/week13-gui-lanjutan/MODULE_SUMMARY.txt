🏗️ ARCHITECTURE IMPLEMENTATION
═══════════════════════════════════════════════════════════════════════════════

PATTERN: MVC (Model-View-Controller) with DAO Layer
─────────────────────────────────────────────────

View Layer
  └─ ProductTableView (JavaFX GUI)
     ├─ TableView<Product> with 4 columns
     ├─ Input form (TextFields)
     ├─ 3 Buttons with Lambda Expressions
     │  ├─ Tambah: btnAdd.setOnAction(e -> handleAddProduct())
     │  ├─ Hapus: btnDelete.setOnAction(e -> handleDeleteProduct())
     │  └─ Refresh: btnRefresh.setOnAction(e -> loadData())
     └─ ObservableList<Product> for reactive updates

      ↓

Controller Layer
  └─ ProductController
     ├─ addProduct(code, name, price, stock)
     ├─ deleteProduct(code)
     ├─ getAllProducts()
     └─ updateProduct(product)

      ↓

Service Layer
  └─ ProductService
     ├─ Validation: code, name, price > 0, stock >= 0
     ├─ insert(Product) - with validation
     ├─ delete(String)
     ├─ findAll()
     └─ update(Product)

      ↓

DAO Layer
  ├─ ProductDAO (Interface) ← DIP
  │  ├─ insert(Product): boolean
  │  ├─ findByCode(String): Product
  │  ├─ findAll(): List<Product>
  │  ├─ update(Product): boolean
  │  └─ delete(String): boolean
  │
  └─ ProductDAOImpl (JDBC Implementation)
     └─ PreparedStatement for all operations

      ↓

Database Layer
  └─ PostgreSQL (agripos)
     └─ products table (code, name, price, stock)

SOLID PRINCIPLES: 5/5 Implemented
─────────────────
✅ S - Single Responsibility Principle
   - Product: Only model
   - DAO: Only DB contracts
   - Service: Only validation
   - Controller: Only coordination
   - View: Only UI rendering

✅ O - Open/Closed Principle
   - Classes open for extension
   - Closed for modification
   - Can add new DAO implementations

✅ L - Liskov Substitution Principle
   - ProductDAOImpl properly substitutes ProductDAO
   - All contracts fulfilled

✅ I - Interface Segregation Principle
   - ProductDAO has 5 focused methods
   - No fat interfaces

✅ D - Dependency Inversion Principle
   - View depends on abstraction (ProductDAO)
   - Loose coupling throughout stack
